# Аудит footballacademymorev.ru — 11.11.2026

## 1. Заявки в MAX не приходят: причины

Сайт и API работают. `POST /api/leads` принимает заявки, а `/api/integrations/max/webhook` отвечает и проверяет секрет. Значит, ломается шаг «заявка → сообщение в MAX». Что нашлось в коде и инфраструктуре:

| # | Проблема | Последствие |
|---|----------|-------------|
| 1 | **Два прода с разными БД.** Токен бота MAX и список одобренных получателей хранятся в БД (`integrations.max_lead_bot`, `max_notify_subscribers`). Раньше заявки шли с `morev.neeklo.ru` (89.169.39.244). `footballacademymorev.ru` (83.222.26.13) поднят `bootstrap-football-vps.sh` с **пустой** БД. | На новом сервере нет токена и/или нет одобренных получателей. Тогда отправлять некуда, а в коде было только `logger.warn`. **Самая вероятная причина.** |
| 2 | Запасной домен был жёстко прописан как `https://morev.neeklo.ru`. Сейчас этот домен отдаёт ошибку TLS. | Если в админке не заполнено поле «HTTPS URL сайта», webhook MAX регистрировался на мёртвый домен: бот не видел команду `notify`, получателей добавить было нельзя. |
| 3 | После переезда у бота могла остаться подписка webhook на старый адрес. | Сообщения боту уходили на старый сервер. |
| 4 | Без Redis (или при его падении) очередь BullMQ молча не отправляла ничего. | Заявка сохранялась в CRM, но уведомление не уходило совсем. |
| 5 | Ошибки отправки в MAX (истёкший токен, 403 и т.п.) писались только в лог PM2. | В админке всё выглядело нормально. |

### Что исправлено (этот коммит)
- Админка → «Уведомления заявок» → MAX: новый блок **«Диагностика»**. Показывает, жив ли токен (`/me`), подключён ли webhook именно на этот сайт, есть ли старые подписки, сколько одобренных получателей, когда была последняя отправка и с какой ошибкой. Плюс кнопка **«Отправить тестовое сообщение»**.
- «Подписаться заново» удаляет подписки бота на старые домены и подписывает на текущий.
- URL сайта по умолчанию берётся из `.env` (`ADMIN_PUBLIC_BASE_URL` → `CORS_ORIGIN`). Жёстко прописанный `morev.neeklo.ru` убран.
- Если Redis недоступен (или не ответил за 5 с), уведомление отправляется напрямую, без очереди.
- Результат каждой отправки в MAX сохраняется и виден в админке.

### Что сделать на сервере после деплоя (5 минут)
1. Задеплоить ветку на 83.222.26.13 (`deploy/server-git-deploy.sh`).
2. Войти в `/admin` → Настройки → Уведомления → MAX.
3. Если токена нет, вставить токен бота (MAX → бот → «Токен») и сохранить. URL сайта подставится сам.
4. Нажать «Подписаться заново».
5. В приложении MAX написать боту `notify`, затем в админке нажать «Одобрить».
6. Нажать «Отправить тестовое сообщение». Должно прийти сообщение в MAX.

## 2. Скорость (Lighthouse, мобильный, живой сайт)

| Метрика | Значение | Цель |
|---|---|---|
| Performance | **64** | 90+ |
| LCP | **4,7 с** | < 2,5 с |
| TBT | **720 мс** | < 200 мс |
| FCP | 1,2 с | ок |
| CLS | 0 | ок |
| Accessibility / Best practices / SEO | 92 / 100 / 100 | — |

Основные потери:
- JS выполняется 1,3 с на главном потоке. Тяжёлые клиентские чанки — анимации (framer-motion в `HomeShell`, `Reveal`, `MobileMenu`, `ApplyModal`, `ApplicationForm`). Около 66 КБ JS не используется.
- Предзагружается 6 woff2-шрифтов (~163 КБ, 4 семейства).
- `hero-kid.jpg` и `p-ballwork.jpg` не в WebP/AVIF: можно сэкономить ~94 КБ.
- Главная отдаётся с `Cache-Control: private, no-cache`, то есть рендерится на каждый запрос.
- Accessibility: недостаточный контраст части текста, мелкие тач-цели на мобильном.

## 3. SEO / GEO

Хорошо: title/description/keywords, canonical, OG/Twitter, robots.txt, sitemap.xml, JSON-LD (`Organization`, `SportsActivityLocation`, `WebSite`).

Не хватает:
- `llms.txt` (404) и FAQ-разметки (`FAQPage`). Это нужно GEO: ответы ИИ-поисковиков (Яндекс Нейро, ChatGPT, Perplexity) опираются на структурированные ответы.
- На главной только один `<h2>`, поэтому семантическая структура слабая.
- Нет отдельных посадочных страниц под запросы («футбол для детей 6–8 лет Анапа», «школа вратарей Анапа», «цены», «расписание»).
- Нет разметки `Offer`/цены, `Review`/`AggregateRating`, `Event` (пробное занятие).
- Нужно проверить Яндекс.Вебмастер / Яндекс.Бизнес / Google Search Console (нужен доступ владельца).
